경쟁사 정보 수집 법적 검토

경쟁사 광고·언급을 모으는 방식별로 법·판례·플랫폼 약관상 제약을 정리했습니다. 이 문서는 법률 자문이 아니라 알에스팀 사내 마케팅 봇 기획을 위한 사전 조사다. 2026-11-27에 로그인 없이 공개 원문(국가법령정보센터, 대법원, 플랫폼 공식 약관·개발자 문서, 개인정보위·공정위 자료, 언론 보도)을 읽고 인용했다. 법령·약관은 수시로 바뀌며, 실제 기능을 만들거나 외부에 공개하기 전에는 변호사 검토를 받아야 한다. 확인하지 못한 사항은 "미확인"으로 표시했다.

주의: 법률 자문이 아닙니다. 사내 마케팅 봇 기획용 사전 조사입니다(조사일 2026-11-27). 로그인 없이 볼 수 있는 법령·판결·약관 원문만 읽었습니다. 실제로 만들기 전에는 변호사 검토를 받아야 합니다. 원문 인용 58개와 출처 링크는 legal.json에 있습니다.

한눈에 보는 표

방식위험도한 줄 설명이렇게 하면 비교적 안전
A. 사람이 직접 보고 정리🟢 낮음공개된 글·광고를 사람이 보는 건 정상 이용이에요. 글 1~2개 옮겨 적는 건 DB 침해로 안 봐요.로그인해야 보이는 글은 제외. 요약과 링크만 적기. 경쟁사 목록·가격표를 통째로 베끼지 않기. 닉네임은 적지 않기.
B. Meta 광고 라이브러리·Google 광고 투명성 센터🟢 낮음 (웹 화면을 긁으면 🔴)공식 도구라 조회는 괜찮아요. 그런데 Meta는 허락 없는 자동 수집을 금지하고, Google은 "정보·연구 목적"으로만 쓰고 팔면 안 된대요.화면은 사람이 보기. 자동화는 Meta 공식 API로만 하기(단, 한국 일반 광고는 API로 안 나올 수 있음). 결과를 외부에 팔지 않기.
C. 네이버 검색 API(블로그·카페글)🟡 중간네이버가 허락한 길이라 "침입"은 아니에요. 그런데 약관이 엄격해요. 저장 금지(예외: 최대 21일), 가공 금지, AI에 넣기 금지. 하루 25,000번까지 호출할 수 있어요."네이버 검색결과"라고 표시하고 원문 링크와 함께 그대로 보여주기만. DB에 쌓아 두거나 AI로 요약하면 약관 위반. 신규 키는 NAVER API HUB에서 받아야 함.
D. 크롤러로 카페·블로그·당근 긁기🔴 높음네이버 카페 robots.txt는 모든 봇을 막아요. 네이버·당근 약관은 허락 없는 자동 수집을 금지해요. 여기어때는 야놀자를 크롤링했다가 형사재판에선 무죄가 났지만, 민사재판에서 10억원을 물어줬어요.하지 않기. 꼭 필요하면 플랫폼에 먼저 서면 허락(제휴)을 받기.
E. 닉네임 같은 개인정보가 섞일 때🟡 중간닉네임도 블로그 주소 같은 다른 정보와 합치면 누군지 알 수 있어서 개인정보가 될 수 있어요. 공개된 글이라도 마음대로 모아도 되는 건 아니에요.닉네임·ID는 저장하지 않거나 가리기. 필요한 것만 모으고 기간이 지나면 지우기. 사람 단위로 분석하지 않기. 요청이 오면 어디서 모았는지 알려주기.
F. (참고) 가짜 후기 올리기 / 경쟁사 베끼기🔴 높음직원이 쓴 홍보글을 손님 후기처럼 올리면 표시광고법 위반이 될 수 있어요(최대 징역 2년 또는 벌금 1억5천만원). AI로 만든 가짜 인물 후기도 마찬가지예요. 경쟁사 문구·디자인·데이터를 베끼면 저작권·부정경쟁 문제가 생겨요.홍보글은 제목이나 첫 줄에 "광고"나 "○○사 직원 작성"이라고 표시하기. AI 가짜 후기는 만들지 않기. 경쟁사는 관찰하고 요약만 하고, 복제하지 않기.

꼭 기억할 판례 2개

  1. 여기어때 vs 야놀자 (2016년 크롤링)
    • 형사사건(대법원 2022. 5. 12. 선고 2021도1533): 무죄. 그래도 대법원은 접근해도 되는지 판단할 때 "보호조치나 이용약관 등"을 본다고 했어요.
    • 민사사건(서울중앙지법 2018가합508729): 부정경쟁행위로 인정돼 10억원 배상, 모은 정보 보관도 금지됐어요. 처음엔 직원이 손으로 모으다가 크롤러로 바꾸면서 문제가 커졌어요.
  2. 잡코리아 vs 사람인: 서울고등법원(2017년 보도)은 허락 없이 채용정보를 크롤링해 영업에 쓴 것을 데이터베이스제작자 권리 침해로 봤어요.

→ 교훈: "형사처벌만 피하면 된다"가 아니에요. 민사 배상과 약관 위반(계정·키 차단)이 진짜 위험이에요.

  • "역추적은 서비스로는 못 들어갈 것 같다" → 크롤러(D) 방식이라면 맞는 말이에요. 사내용이어도 약관 위반과 부정경쟁 위험은 그대로예요.
  • 그래도 역추적 자체가 불법은 아니에요. 아래처럼 범위를 좁히면 사내 기능으로 만들 수 있어요.

    2. 허락이 필요한 것: API 결과를 저장하거나 AI로 요약하기, 카페·블로그·당근 본문 자동 수집. 플랫폼 제휴를 먼저 받아야 해요.
    3. 절대 넣지 않을 것: AI 가짜 후기 자동 게시, 경쟁사 서비스 복제(F)
  • 개인정보는 닉네임을 저장하지 않는 설계로 위험을 크게 줄일 수 있어요.

방식별 상세 근거

A. 사람이 공개 페이지(검색 결과, 공개 카페·블로그 글, 광고)를 직접 보고 수기로 정리 위험 낮음

로그인 없이 누구나 볼 수 있는 페이지를 사람이 보는 것은 플랫폼이 예정한 정상 이용이고, 네이버 약관이 막는 것은 "자동화된 수단"이다. 저작권법상 개별 소재(글 1건, 광고 1건)의 복제는 데이터베이스의 "상당한 부분"으로 보지 않는다. 다만 경쟁사 DB를 반복·체계적으로 베껴 결국 상당한 부분을 복제한 결과가 되거나, 수기로 모은 정보를 경쟁사 성과에 편승하는 방식으로 영업에 쓰면 저작권법 제93조 제2항·부정경쟁방지법 (파)목 문제가 될 수 있다(여기어때 사건에서도 처음엔 수기로 취합하다 크롤링으로 넘어갔다).[1][2][3][4]

  • 로그인·가입이 필요한 비공개 카페/게시판은 보지 않는다(회원만 보는 글은 공개 정보가 아님)
  • 원문 전체를 복사하지 말고 요약·링크·날짜·채널 정도만 기록한다
  • 경쟁사 사이트의 목록·가격표·DB를 통째로 옮겨 적는 체계적 복제는 하지 않는다
  • 작성자 닉네임·프로필은 적지 않거나 가린다(E 참고)
  • 정리 결과는 사내 참고용으로만 쓰고 외부 공개·판매하지 않는다

B. Meta 광고 라이브러리·Google 광고 투명성 센터 등 공식 공개 도구·API 사용 위험 낮음

공식 도구 화면을 사람이 조회하거나 공식 API를 약관대로 쓰는 것은 허용된 이용이다. 하지만 (1) Meta Ad Library API는 EU에 노출되지 않은 광고는 사회 이슈·선거·정치 광고만 돌려주므로 한국 경쟁사의 일반 상업 광고는 API로 받을 수 없을 가능성이 크고(실제 응답은 미확인), (2) Meta는 서면 허가 없는 자동 수집(웹 화면 스크래핑)을 금지하며, (3) Google 광고 투명성 센터는 "조직의 정보 또는 연구 목적"으로만 쓰고 판매·수익화를 금지하고, Google 서비스 약관은 robots.txt 등에 반하는 자동화 접근을 금지한다. 따라서 "공식 API·수동 조회"는 낮음, "웹 화면 스크래핑"은 D와 같은 높음으로 본다.[5][6][7][8]

  • Meta: 화면은 사람이 수동 조회하고, 자동화는 공식 Ad Library API(ads_archive)로만 한다(본인 인증·앱 등록이 필요할 수 있으며 이번 조사에서는 로그인하지 않아 절차는 미확인)
  • Meta 광고 라이브러리 웹 화면을 봇·헤드리스 브라우저로 긁지 않는다(서면 허가 필요)
  • Google 광고 투명성 센터: 사내 정보·연구 목적으로만 쓰고 결과를 외부에 팔거나 유료 기능으로 만들지 않는다
  • Google 광고 투명성 센터에는 공식 공개 API가 있는지 미확인이므로, 확인 전에는 수동 조회 + 링크 기록만 한다
  • 광고 소재(이미지·문구)는 광고주 콘텐츠이므로 사내 보고서에 인용하는 정도로 쓰고 재게시·재배포하지 않는다

C. 네이버 검색 오픈API(블로그·카페글 검색) 사용 위험 중간

네이버가 명시적으로 허용한 자동 접근 경로라서 "침입"·약관상 자동수집 금지 문제는 사라진다. 그러나 NAVER API 서비스 이용약관(2026-10-07 개정본)의 검색 API 특약이 매우 엄격하다: 검색결과 제공 목적으로만, 가공 없이 노출, 데이터 복사·저장·캐싱 금지(서버 이력 조회용 최대 21일 등 예외), 데이터를 AI에 입력·학습·평가에 쓰는 행위 금지. 따라서 "API로 받은 글을 DB에 쌓아두고 AI로 요약·분류"하는 봇 설계는 약관 위반이 된다. 하루 호출 한도는 25,000회이고 결과는 제목·요약 패시지·링크 수준이다. 또 2026-07-30 이후 신규 신청은 NAVER API HUB(네이버 클라우드)로 옮겨졌고, API HUB 쪽 별도 약관 내용은 이번에 미확인.[9][10][11][12][13]

  • 신규 키는 NAVER API HUB에서 발급(회사 단체 계정 권장, 발급 절차는 로그인 필요로 미확인)
  • 하루 25,000회 한도 안에서 호출하고 경쟁사명·브랜드 키워드 위주로 질의
  • 결과는 "네이버 검색결과"임을 표시하고 원문 링크와 함께 가공 없이 보여주는 화면(예: 사내 대시보드의 실시간 검색 패널)으로만 쓴다
  • API 결과를 장기 저장하지 않는다(서버 보관은 이력 조회 목적 최대 21일, 기간 경과 시 즉시 삭제)
  • API 결과(제목·요약문 포함)를 LLM에 넣어 요약·분류·감성분석하지 않는다 — 필요하면 네이버에 제휴/별도 허락을 문의
  • API가 준 링크를 따라가 본문을 크롤러로 긁으면 D 방식이 되므로 하지 않는다(사람이 클릭해서 보는 것은 A)
  • NAVER API HUB 약관을 별도로 확인하기 전에는 위 개발자센터 약관 기준을 그대로 적용

D. 네이버 카페·블로그·당근 등 페이지를 크롤러로 자동 수집 위험 높음

(1) robots.txt: cafe.naver.com은 모든 봇(User-agent: *)에 전체 Disallow, 당근은 /kr/community/s/ 등 일부 경로를 막고 Scrapy 등 다수 봇을 전면 차단, blog.naver.com은 일부 경로만 막지만 네이버 약관은 별도로 자동 수집을 금지. (2) 약관: 네이버는 사전 허락 없는 자동화 수단으로 게시물 수집을 금지하고 이를 정보통신망법상 "정당한 접근권한 없는 침입"이 될 수 있다고 고지, 당근도 사전 서면 동의 없는 크롤링·분석을 금지. (3) 법: 정보통신망법 제48조(침입 금지, 위반 시 5년 이하 징역/5천만원 이하 벌금), 저작권법 제93조(DB제작자 권리), 부정경쟁방지법 제2조 제1호 (카)목(데이터 부정사용)·(파)목(성과 도용). (4) 판례: 여기어때 크롤링 형사사건(대법원 2022. 5. 12. 선고 2021도1533)은 무죄였지만, 대법원은 접근권한 판단에 "보호조치나 이용약관 등"을 고려한다고 했고, 같은 사실관계의 민사사건(서울중앙지법 2018가합508729)은 부정경쟁행위로 10억원 배상과 정보 보관 금지를 명했다. 잡코리아-사람인 사건(서울고법, 2017)도 무단 크롤링을 DB제작자 권리 침해로 봤다. 형사 무죄 = 안전이 아니다.[1][2][3][4][9][14][15][16][17][18][19][20][21]

  • 원칙: 네이버 카페·블로그·당근 본문 크롤링은 하지 않는다(사내용이어도 동일)
  • 꼭 필요하면 플랫폼의 명시적 사전 허락(서면·제휴)을 먼저 받는다

  • 자사 사이트·공식 보도자료처럼 robots.txt와 약관이 허용하는 페이지만 소량 수집하는 경우에도 약관을 먼저 확인

E. 수집한 글에 작성자 닉네임·프로필 링크 등 개인정보가 포함될 때(개인정보보호법) 위험 중간

닉네임 하나만으로는 누군지 모를 수 있지만, 블로그 주소·프로필·글 내용 등 "다른 정보와 쉽게 결합하여" 알아볼 수 있으면 개인정보다. 우리 회사가 업무 목적으로 이를 모아 파일(DB)로 운용하면 개인정보처리자가 되고, 수집 근거(제15조 제1항, 공개 정보는 보통 제6호 "정당한 이익")와 최소 수집(제16조), 정보주체 요구 시 수집 출처 통지(제20조), 목적 달성 후 파기(제21조)를 지켜야 한다. 개인정보위 「AI 개발·서비스를 위한 공개된 개인정보 처리 안내서」(2024.7, 법적 구속력 없음)는 공개된 개인정보도 개인정보자기결정권의 보호대상이며, 직접 스크래핑 시 이용약관과 robots.txt를 지켜야 한다고 안내한다. 이 안내서는 AI 학습용 기준이므로 마케팅 모니터링에 그대로 적용되는지는 미확인(유추 참고).[16][22][23]

  • 목적은 "경쟁사 브랜드 언급 추세 파악"으로 한정하고, 개인(작성자) 단위 분석·프로파일링은 하지 않는다
  • 닉네임·블로그 ID·프로필 사진·연락처는 저장하지 않거나 즉시 가명/해시 처리한다(필요 최소한만)
