주제확인한 것 [사실]우리에게 주는 의미
사장님이 모이는 곳네이버 카페 '아프니까 사장이다' 회원 198만, 배민외식업광장 회원 90만(장사 정보 콘텐츠), 캐시노트 계열 도입 사업장 300만, 토스플레이스는 대리점으로 단말기 유통. 신규 서비스를 알게 되는 경로의 공식 통계는 없음콘텐츠(①)와 제휴(④)가 유력. 실제 경로는 우리 데이터로 확인 필요
비슷한 국내 사례캐시노트 쿠폰 서비스: 랜딩 + 사장님 직접 연락 + 매장 포스터로 매장과 손님을 함께 모음쿠핀도 매장(PLUS)과 손님(ON)을 함께 모아야 하는 같은 구조
B2B 유입 사례Flex는 인바운드 문의로 시작해 고객사 6만 곳. 한 B2B 스타트업은 채널을 줄이고 콘텐츠에 집중해 3개월 만에 문의 월 5건 → 43건. 랜딩 전환율 중앙값 3.8%"찾아오게 하는 콘텐츠 + 문의를 놓치지 않는 흐름"이 기본
시장소상공인 613.4만 곳, 디지털 기술 활용 27.2%. AI 활용 9.7%지만 관심 61.7%, 가장 큰 장벽은 도입 비용 69%"AI"보다 비용 부담 없이 손님이 느는 결과를 보여 줘야 설득됨
경쟁네이버 플레이스 쿠폰·토스플레이스·페이히어는 쿠폰·적립 기본 기능이 무료PLUS 차별점(POS 없이 시작, 외부 판매, AI 리포트)을 앞세워야 함
AI 마케팅 사례소상공인 SNS 글 자동 생성·게시(오토케), 잠재 고객 조사·맞춤 메일(AI 영업 담당자), 네이버의 사장님용 AI 응대콘텐츠·영업 자동화는 이미 검증된 방식, 직접 조립 가능
쿠핀 ON (B2C)소비자 43.6%가 쿠폰을 자주 사용, 당근 동네 쿠폰 다운로드 550만 건동네 쿠폰 수요는 있음. 다만 매장이 먼저
프로토타입 A~D로컬 모델로 4개 모두 실행 확인. A 콘텐츠 초안(약 30초), B 문의 즉시 후속(약 10초), C 영업 브리프(약 30초, 사실 7개 모두 근거 있음), D 뉴스 수집·글감 추출(약 40초). 외부 발송은 하지 않음흐름은 동작. 약점은 문장 품질(사람 검토 필요)과 실제 데이터 부족. 실사용자가 없어 효과는 미측정
공용 엔진여러 서비스가 함께 쓰는 엔진을 만들어 PLUS·ON 시나리오 4개로 확인(5장)지금 시나리오는 가입 후 대상이라 유입용으로 확장 필요

2. 사장님이 PLUS를 쓰기까지 (유입 퍼널)

알게 됨→랜딩 방문→문의 또는 가입 시작→사업자 인증·관리자 승인→구독 결제→첫 쿠폰 발송
단계새는 지점 [아이디어]확인할 데이터
알게 됨사장님이 PLUS를 검색할 이유가 없음. 무료 대체재(네이버 플레이스 쿠폰, 토스플레이스 등)를 먼저 만남유입 경로별 방문 수
문의·가입 시작문의 후 답이 늦으면 식음. 가입 중 사업자등록증 단계에서 멈춤문의 → 상담 소요 시간, 단계별 이탈
승인·결제관리자 승인을 기다리다 떠남. 유료 결제 전에 효과를 못 느낌승인 대기 시간, 승인 → 결제 비율

[사실] PLUS 가입은 랜딩이 넘긴 UTM을 tn_company_attribution에 기록합니다(2026-09 추가, join.service.ts). 이 데이터가 쌓여 있다면 "어디서 온 사장님이 결제까지 가는지"를 바로 볼 수 있습니다.

3. 방향성 — 정형화된 방법

방법내용봇이 자동화할 부분사람이 할 부분
① 인바운드 콘텐츠
SEO·커뮤니티		사장님 고민(손님 감소, 배달·기프티콘 수수료, 단골 관리)에 답하는 글로 검색·커뮤니티에서 찾아오게 함. 글마다 UTM 링크뉴스·커뮤니티에서 고민·글감 수집 → 업종별 글 초안 → 검증(지어낸 숫자 차단)글 승인·게시, 커뮤니티 활동
② 문의·가입 이탈 회수이미 관심 보인 사장님을 놓치지 않기. 문의 즉시 응대, 가입 중단자 이어하기, 승인 지연 방지문의 즉시 업종 맞춤 안내, 가입 24시간 미완료 시 안내, 승인 대기 시 운영자 알림상담 통화, 승인
③ 영업 지원회사 주 유입 경로가 영업이므로, 영업 담당자가 더 많은 매장을 더 잘 준비해서 만나게 함지역·업종별 매장 공개 정보 조사 → 매장별 브리프와 맞춤 제안서 초안연락·방문·계약
④ 제휴 채널사장님이 이미 모여 있는 곳과 함께: 지역 상인회, 지자체·공공 소상공인 지원사업, POS·결제 단말기 대리점, 프랜차이즈 본사지원사업 공고 모니터링, 제휴 제안서 초안제휴 협상

①②③은 이미 프로토타입이 있습니다 (D·A 콘텐츠, B 문의 후속, C 영업 지원). ④는 새로 조사가 필요합니다.

4. 방향성 — 창의적인 방법 [아이디어]

A. "우리 가게 쿠폰 진단" 무료 리포트 리드 확보

랜딩에서 가게 이름·업종만 넣으면, 봇이 업종 특성에 맞춘 쿠폰 전략 3가지를 바로 보여 주고 "실제로 보내 보려면 가입"으로 연결. PLUS의 AI 월간 리포트를 가입 전 맛보기로 쓰는 셈입니다. 자동화: 진단 생성 전부. 확인 필요: 공개 정보를 어디까지 쓸 수 있는지.

B. 손님이 보는 화면에 "사장님이세요?" 바이럴 루프

PLUS 쿠폰을 받는 손님(QR 화면, 쿠폰 메시지) 중에는 다른 가게 사장님도 있습니다. 화면 하단에 "이 쿠폰은 쿠핀 PLUS로 만들었어요 · 사장님이라면 시작하기" 한 줄. 매장이 늘수록 노출이 늘어나는 구조입니다. 자동화: 노출·UTM 추적. 사람: 문구·위치 결정(사장님 동의 필요할 수 있음).

C. 사장님 → 사장님 추천 추천

옆 가게를 소개하면 둘 다 발송 크레딧 지급. PLUS에 이미 크레딧 체계가 있어 보상 수단이 있습니다. 상인회처럼 사장님끼리 아는 상권에 맞습니다. 자동화: 추천 링크 발급, 가입 확인, 크레딧 지급.

D. 소비자 수요를 영업 근거로 (ON → PLUS 역방향) 양면 연결

ON에서 "이 동네 이 가게 쿠폰이 있으면 좋겠어요" 요청을 받아, 요청이 쌓인 가게에 "손님 N명이 기다리고 있습니다"라는 근거로 영업. 소비자 데이터가 사장님 유입의 설득 자료가 됩니다. 자동화: 요청 집계, 매장별 영업 브리프. 단, ON 사용자가 적은 지금은 효과가 작고 이후 단계용입니다.

5. 챗봇(엔진) 설계 — 간단히

하나의 공용 엔진에 서비스별 연결부를 붙이는 구조로 만들었고, 쿠핀 PLUS·ON 시나리오 4개로 동작을 확인했습니다(로컬 모델, 실제 발송 없음). 봇은 신호 → 조건 확인 → 문구 생성 → 검증 → 사람 승인 → 발송·게시 → 성과 측정 순서로 일합니다. 모델은 문구를 쓰는 단계에서만 부르고, 누구에게·언제는 규칙이 정합니다.

유입 목표로 바꾸려면내용
아직 고객이 아닌 대상지금은 가입 회원만 다룸 → 문의자·가입 중단자·영업 대상 매장을 다루는 연결부 추가
대상 없는 예약 작업"매주 글감 수집·초안 3개" 같은 콘텐츠 작업용 예약 실행
콘텐츠 채널블로그·커뮤니티 초안을 승인 후 게시
유입 지표UTM별 방문 → 문의 → 가입 → 결제 비교 (PLUS 가입 UTM 기록과 연결)

이미 만든 가입 후 시나리오(첫 쿠폰 도우미, 리포트 실행 등)는 유입 목표에 맞춰 우선순위를 낮췄습니다.

6. 막히는 부분

막힌 것왜 문제인지풀려면
실제 유입 경로 데이터사장님이 지금 어디서 오는지 몰라서 방향 우선순위를 감으로 정하게 됨tn_company_attribution 집계, 영업 유입 비율 공유
영업 방식영업 지원(③)이 효과가 클 수 있지만 지금 영업을 누가·어떻게 하는지 모름영업 담당자와 짧은 인터뷰
법규사업자에게 보내는 메일·문자도 광고면 사전 동의 필요(정보통신망법 제50조). 봇이 모르는 매장에 직접 연락하는 방식은 불가인바운드·영업 지원 위주로 설계, 법무 확인
채널 계정·운영자콘텐츠를 올릴 블로그·커뮤니티 계정, 승인할 사람이 정해지지 않음담당자 지정
성과 판단 기준무엇이 늘면 성공인지(문의 수, 가입 수, 결제 수) 정해지지 않음목표 지표 1개 합의
서비스 코드 수정문의·가입 단계 연결(②)은 PLUS 코드에 이벤트 전송을 추가해야 함범위 승인
AI 모델·비용운영 모델 미정, 비용 추정은 보류 중방향이 정해진 뒤
